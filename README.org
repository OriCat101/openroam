#+title: openroam

A research & note-taking agent for [[https://www.orgroam.com/][org-roam]], built as a customized
[[https://opencode.ai][opencode]] talking to [[https://proton.me/lumo][Proton Lumo]] through [[https://github.com/ZeroTricks/lumo-tamer][lumo-tamer]].

One flake bundles everything: opencode, the generated config (provider, agents,
commands), a Nix-packaged [[https://github.com/aserranoni/org-roam-mcp][org-roam-mcp]] server that gives the agent
=search_nodes=, =get_node=, =get_backlinks=, =list_files=, =create_node=,
=update_node= and =add_link= over your knowledge base — and the lumo-tamer
server itself (via [[https://github.com/OriCat101/lumo-tamer-nix][lumo-tamer-nix]]).

** why lumo?
In our org-roam are over 1000 notes ranging from shopping lists to software license keys.
I don't want this to go into a training-set. Lumo is the closest thing we have to a
"private" LLM. (okay self-hosting is an option and I would prefer this if I wasn't broke)
[[https://proton.me/blog/lumo-security-model#user-to-lumo][Lumo encrypts your convo tight up until the LLM]] and is [[id:6bb757d6-da77-43fd-a455-23300b6a0f47][GDPR]] compliant.

Additionally by default Lumo-Tamer does not create persistent Lumo sessions,
so session management is purely local, and does not persist on Proton's servers.

* Prerequisites

A running lumo-tamer server with custom tools enabled — in its =config.yaml=
(=~/.local/state/lumo-tamer/config.yaml=):

#+begin_src yaml
server:
  apiKey: "your-super-secret-key"
  customTools:
    enabled: true        # required: opencode is tool-driven
  instructions:
    injectInto: "last"   # keep tool instructions fresh in long sessions
#+end_src

#+begin_src sh
nix run github:OriCat101/openroam#server
#+end_src

* Usage

#+begin_src sh
nix run github:OriCat101/openroam          # opens in $ORG_ROAM_DIR (default ~/roam)
nix run github:OriCat101/openroam -- ~/some/other/dir
#+end_src

Agents (switch with =Tab=):

- *researcher* — searches your notes before answering, cites them by title,
  explores backlinks, saves new findings as linked atomic notes.
- *capture* — turns pasted text/URLs into well-formed org-roam notes linked
  into the existing graph.
- *crawler* — read-only subagent (not Tab-switchable): dispatched by the
  researcher via the =task= tool, it traverses the graph (searches, links,
  backlinks) in its own context and returns a compact digest, keeping the main
  session lean.

Commands: =/related <topic>=, =/capture <text or url>=, =/deepsearch <topic>=
(crawl the graph, then synthesize a cited answer), =/map <topic>= (crawl, then
save a hub/index note linking what was found).

* Opening cited notes in Emacs

Agents cite notes as Markdown links to =org-protocol://roam-node?id=UUID=
instead of plain text — most terminals (kitty, wezterm, iTerm2, foot, ghostty)
render these as clickable OSC 8 hyperlinks, so clicking one in the TUI jumps
straight to that node in Emacs, like clicking a web URL.

This needs org-protocol wired up on the Emacs side:

1. Emacs must be running as a server: =(server-start)= or =emacs --daemon=.
2. =(require 'org-roam-protocol)= (pulls in =org-protocol= and registers the
   =roam-node= handler org-roam ships).
3. The OS must hand =org-protocol:= URIs to =emacsclient=. On Linux, register
   a desktop entry as the scheme handler, e.g. via home-manager:

   #+begin_src nix
   xdg.desktopEntries.org-protocol = {
     name = "org-protocol";
     exec = "emacsclient %u";
     terminal = false;
     mimeType = [ "x-scheme-handler/org-protocol" ];
   };
   #+end_src

   then =xdg-mime default org-protocol.desktop x-scheme-handler/org-protocol=.

Note-internal links (what =create_node=/=update_node= write into the =.org=
files themselves) stay plain org-roam =[[id:UUID][Title]]= links — org-roam's
own graph and backlinks depend on that syntax, not =org-protocol=.

* Configuration

Everything is overridable via environment variables:

| Variable         | Default                  |
|------------------+--------------------------|
| =LUMO_BASE_URL=    | =http://localhost:3003/v1= |
| =LUMO_API_KEY=     | lumo-tamer's default key |
| =ORG_ROAM_DIR=     | from Emacs, else =~/roam=  |
| =ORG_ROAM_DB_PATH= | from Emacs, else =~/.emacs.d/org-roam.db= |

When =ORG_ROAM_DIR= / =ORG_ROAM_DB_PATH= are unset, openroam asks a running
Emacs daemon (via =emacsclient -e=) for =org-roam-directory= and
=org-roam-db-location= and uses those; the hardcoded defaults above only kick
in when no daemon answers. An explicitly set variable always wins.

* Caveats

- *Tool calling is experimental* in lumo-tamer (tools are injected as text
  instructions and parsed back out of Lumo's replies). It can misroute or fail;
  the agent tool set is deliberately kept small to help. =lumo-max= behaves best.
- *Lumo's context is small* (~22k tokens warning level). Keep sessions short,
  start a new one per topic.
- *DB staleness*: org-roam only re-indexes files saved inside Emacs. After the
  agent creates notes, run =M-x org-roam-db-sync= (or
  =emacsclient -e '(org-roam-db-sync)'=) to make them visible to org-roam.
- Notes created by the agent get proper =:ID:= properties from org-roam-mcp,
  but review them — it's a young project.
- Optional: set =server.enableWebSearch: true= in lumo-tamer's config to let
  Lumo use Proton's native web search during research.
